## 2026-08-15 - [🛡️ Sentinel] Added file size validation and fixed `URL.createObjectURL` memory leak
**Vulnerability:** The application was vulnerable to client-side resource exhaustion (Denial of Service) because it lacked a file size limit when loading images into memory. Additionally, it suffered from a memory leak because Blob URLs generated with `URL.createObjectURL` were never revoked.
**Learning:** Client-side file uploads require defense-in-depth just like server-side endpoints. Browser memory is limited, and unconstrained processing of large files can crash the user's browser. Furthermore, replacing a string holding a Blob URL doesn't free the memory; it must be explicitly revoked.
**Prevention:** Always enforce a reasonable file size limit (e.g., `MAX_FILE_SIZE = 10 * 1024 * 1024`) before processing user-provided files. Ensure that a helper function (like `clearSelection`) is used to both unset the state variable and explicitly call `URL.revokeObjectURL()` on the old reference.
